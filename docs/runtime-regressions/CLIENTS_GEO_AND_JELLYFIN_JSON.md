# Contrats Jellyfin, applications et géographie — 12 octobre 2026

Le signalement réel indique 8 résolutions réparées et 530 médias conservés sans correspondance certaine. La synchronisation récente échoue sur `/Items`, élément 33, parce que `Studios[0]` est un objet tandis que le lecteur Go attendait une chaîne. Le format objet `{Name,Id}` et le format chaîne des anciens exports sont maintenant acceptés ; les studios malformés restent refusés. Les autres champs d'Item gardent leur décodage normal.

Les résolutions sont comptées uniquement pour les types vidéo connus. Audio, Track, MusicTrack, MusicAlbum, Music, Song, Book et AudioBook sont exclus, même si un ancien enregistrement contient une résolution. Un type absent ou Unknown ne suffit plus pour classer une lecture comme vidéo. Les lectures vidéo sans résolution restent visibles comme telles.

« Écosystème des applications » utilise maintenant une distribution dédiée des clients/applications, conservant séparément la distribution des machines dans l'API. Le navigateur est affiché lorsqu'il est explicitement enregistré dans le nom d'appareil d'un client Web (Chrome, Firefox, etc.). Le clic utilise le client et, si pertinent, le navigateur enregistré comme filtres d'historique. Un nom de machine tel que DESKTOP-MAEL n'est jamais interprété comme Windows. Windows/Linux/macOS ne peuvent être reconstruits si l'ancienne session ne les enregistrait pas ; les noms d'application qui les contiennent les affichent normalement.

La tâche de réparation renvoie jusqu'à vingt exemples non identifiés avec leur motif : identifiant absent du catalogue Jellyfin accessible, identifiant provisoire manquant dans l'ancien import, ou bibliothèques ambiguës. Le détail est affiché sur la carte de la tâche. Le nombre 530 ne prouve pas que ces médias n'avaient jamais de bibliothèque ; il indique l'absence de correspondance exploitable pendant cette exécution. Une synchronisation complète réussie peut restaurer des parents/metadonnées manquants. Aucun rapprochement de titres seuls ni suppression d'historique n'est effectué.

L'API géographique agrège toutes les sessions, dont celles avec pays null ou Unknown, par IP et localisation enregistrée. Les IP privées/loopback sont distinguées comme réseau local. Les IP absentes, invalides ou non situables restent sans localisation. Les pays enregistrés réellement connus sont conservés. Les lignes Unknown, Unknown ne sont plus présentées comme un lieu.

Un lecteur MMDB local utilise `GEOIP_DATABASE_PATH`, par défaut `/data/GeoLite2-Country.mmdb`. Le fichier `internal/geoip/country.mmdb` du dépôt est vide : aucune base géographique valide n'est incluse. En l'absence de fichier valide sur le serveur, l'interface indique le manque de GeoIP ; aucun pays n'est inventé, et aucune IP n'est envoyée à un service externe. Une base Country ne fournit pas nécessairement de ville ; une base City peut la fournir. L'enrichissement est calculé à la lecture, sans réécrire l'historique. Les localisations des flux actifs et les classements par pays restent disponibles.
